# 织章 V2.1.0

织章是 DeepSeek Harness 上的作者工作台，包含番茄连载和头条创作两条流程。使用同一套版本记录、候选对照和作者决策，把设定、草稿、审稿和交稿串起来。

[安装、架构、规则裁决与验收](docs/V2.md) · [优化计划](docs/V2-优化计划.md)

`npm run verify` 执行 TypeScript 检查与核心离线测试。历史规则取证可用 `npm run test:evidence` 单独复核，完整离线验收用 `npm run test:all`。`npm run build` 构建宿主代码，之后可用 `npm pack --ignore-scripts` 打包，并在 DsH Web 0.2.2-rc.4 的插件管理器安装。

## 交付前取证记录

以下条目保留初次 V2 提交时的历史进度和原始验收用例说明。

This is the independent V2 development workspace. It is intentionally separate from the original v1.x workspace, which remains a historical reference only.

**Current state.** The P1-A skeleton is in place. D-01 and W-01 use `node:sqlite` to test local transactions, checkpoint recovery, and cancellation. F-01 exercises chapter and character viewpoints and author decisions with fixed inputs. **The frozen storage slices are implemented in `src/storage/`** (schema window, open/create, backup verify/restore/retention, delivery-export state machine, the delivery command that joins the approval gate to its external export, the command journal with the frozen write order, the command dispatcher that puts the frozen command table in front of it, the event log with its cursor protocol, the projection store with its durable checkpoints, and the recovery matrix), **the frozen workflow contracts are implemented in `src/workflow/`** (the run state machine, the stage registry, the budget guard, the read-model surface, and the serve that joins a read to the log), **the frozen continuity mechanics are implemented in `src/domain/`** (anchors, the chapter-order comparison, the half-open validity interval, and chapter reordering with its author-facing impact list), and **the frozen shared contracts live in `src/contracts/`** (the error envelope, the approval record with its gate, and the section 2 command table with its check order), all conformance-tested against the evidence fixtures. Host identity and Bundle installation remain unverified; the target SQLite driver is still an open decision (Q-05) and is kept behind one seam.

- TypeScript `5.8.3` is the pinned development compiler, locked in `package-lock.json`; it is build tooling, not the embedded DsH runtime version.

## Commands

- `npm ci --ignore-scripts` installs the pinned compiler without running package lifecycle scripts; a registry may be needed on first setup.
- `npm run check` runs strict TypeScript checking without emitting files.
- `npm test` runs the module-boundary and offline sample tests with Node's built-in test runner.
- `npm run build` emits JavaScript to ignored `dist/`; it does not package or validate a DsH Bundle.
- `npm run verify` combines check and test.

Verification scripts make no model calls, network calls, DSH profile changes, or publishing actions. No Host or Client API is guessed. The smoke test only verifies that the empty module boundaries load; it does not demonstrate application functionality.

## Module layout

- `src/contracts/`: future shared contracts.
- `src/host/`: future verified host adapter and composition root.
- `src/storage/`: future persistence boundary.
- `src/workflow/`: future orchestration boundary.
- `src/domain/shared/`: future shared business primitives.
- `src/domain/fanqie/`: future long-form writing domain.
- `src/domain/toutiao/`: future article domain.
- `src/client/`: future author workbench client.
- `src/bundle/`: future package assembly boundary.

These modules currently export nothing. Their boundaries follow the local P1-A plan, not frozen APIs. Detailed plans remain in the original v1.x workspace under its local ignored `plans/v2.0/` directory; they are not copied into this repository or treated as a public dependency.
