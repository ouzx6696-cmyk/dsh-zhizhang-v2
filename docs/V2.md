# 织章 V2.1.0 交付与验收

织章把作品规划、正文修订、模型候选稿和作者决定放在同一工作台。番茄连载围绕章节推进、人物所知与设定连续性。头条创作围绕场景规划、质检、验收和交稿。工作稿与候选稿分别存储，采纳以候选的基准修订为准，定稿和交稿由作者操作。交稿只在本地生成 Markdown。

## 架构

| 层 | 职责及本次交付 |
| --- | --- |
| `src/domain/fanqie/` | 章纲、篇幅提醒、审稿和定稿门、叙事锚点上的知情视图、重排影响 |
| `src/domain/toutiao/` | 三种体裁与两条内容线、标题候选、结构门、质检和双轮回改、交稿文本 |
| `src/contracts/` | 命令权限与校验顺序、共享错误、绑定到版本的批准 |
| `src/storage/` | SQLite 文稿修订、命令幂等账本、项目事件日志、投影检查点、交稿导出 |
| `src/workflow/` | 运行状态机、阶段注册、预算和读模型定义 |
| `src/application/` | 处理作者操作、版本检查、事务和查询 |
| `src/host/` | 挂载 DsH 工作台，传输模型请求并写入交稿文件 |
| `src/client/` | DsH 侧栏入口、会话视图和作者页面；目录、正文、流程、候选对照、本地草稿恢复 |
| `src/bundle/` | 插件注册、语言元数据和默认数据目录 |

工作台从 SQLite 读取编辑状态。导航、版本与候选、设定视图、证据、运行和审批历史六个只读模型由项目事件回放提供，统一返回 asOfSeq。证据记录绑定正文版本和唯一匹配的摘句。

## 安装和运行

1. 使用 DsH Web `0.2.2-rc.4` 与 Node ≥24.15。自行从源码构建时还需 npm ≥11。
2. 在 DsH 的插件管理器选择 **添加插件**，使用本地包 `zhizhang-dsh-workbench-2.1.0.tgz`，启用 **织章工作台**。
3. 从左侧 **织章** 进入，或从已有会话的 **织章** 视图进入。首次使用时，新建番茄项目或头条项目，再创建稿件。
4. 使用已配置的 DsH 模型时，先保存正文，创建写作任务，在流程区确认模型提供方和模型，再启动生成。也可以导入候选正文和已知的令牌用量。
5. 在头条流程记录质检并验收。交稿前批准当前版本。交稿文件可从页面下载，也保存在数据目录下。

数据目录为 `DSH_HOME/zhizhang-v2/`。正文与运行信息保存在 `workspace.sqlite`，交稿文件在 `deliveries/`。搬运完整 SQLite 库时先停止该 profile。浏览器保存的未提交编辑按稿件键和基准修订恢复，版本已变化时会提示核对。

## 裁决

| 项 | 本次采用 |
| --- | --- |
| 番茄单章篇幅 | 默认建议 2,000–2,500 个 Unicode 非空白字符。1,500–6,000 是章纲提醒区间 |
| 篇章节奏 | 快爽、稳推、慢燃是软建议。年代、都市、种田默认稳推，群像默认慢燃。快爽的固定笔墨比例未纳入 |
| 章纲 | 工作台有四块结构和四个头注字段。正文编辑独立，可保有作者自己的组织方式 |
| 设定 | 已确认版本按故事中的半开区间和人物知情点过滤。设定提案在确认前独立。已锁定设定拒绝覆盖 |
| 头条矩阵 | 长图文、短图文、微头条 × 资讯线、故事线。体裁和内容线显式选择。标题候选需至少五个不同标题并覆盖三种母题 |
| 微头条 | 微头条独立成型，表单不要求题名。34 个 Unicode 字符上限用于有标题的体裁。首句仍可作为编辑指导 |
| 作者决定 | 最多两次审稿打回和两轮自动回改。头条在 84 分、通过标记、零未通过项、零硬门时进入待验收。每个交稿版本单独批准 |
| 运行与预算 | 取消由作者控制。一次调用按四类令牌计入用量。模型费用和费率留给 DsH 提供方 |
| 宿主与存储 | 使用 DsH Web 0.2.2-rc.4 的 owner-only Connection 路由、Cordis 生命周期和 UI slots。SQLite 使用 Node 的 `node:sqlite` |
| 平台条款和资产 | 平台条款以当期创作者后台为准。章纲使用结构化输入，篇章顺序依内部章 ID，旧标题正则和独立质检标准表不作为运行约束 |

已保护的门槛和状态保留在领域模块。正文交稿只输出一次固定尾句。旧的私人 `plans/v2.0/` 未随源码快照提供，裁决依据为仓库已有证据夹具和交付报告。

## 验收

```bash
npm ci --ignore-scripts
npm run verify
npm run test:all
npm run build
npm pack --ignore-scripts
```

日常开发运行 `npm run verify`，覆盖真实存储、工作流、规则和作者端操作。历史规则取证用 `npm run test:evidence`，发版前用 `npm run test:all` 执行两部分。安装包仍需在 DsH 隔离配置中验证挂载和浏览器流程。

模型调用只使用一次性 LLM 传输，无会话工具或写权限。默认项目操作只通过 DsH 已认证的浏览器 owner 暴露。其他 DsH 扩展和有本机文件权限的进程仍处在宿主的信任边界内。官方参考为 dsh-v0.2.2-rc.4 的 dsh-doc、Connection 和 UI Slot 源码，标签提交为 `3f321d32bfe382212a8ed8785c1d47a5a300aa23`。


## 使用与恢复

- 保存期间可以继续写作。请求确认之前提交的文字，随后输入的文字继续留在编辑器和本地草稿。出现版本冲突时，可查看服务器正文、复制本地稿，再由作者决定如何合并。
- 番茄的同一份设定提案可为多个人物分别填写知情章段。省略知情章段时沿用生效点。可选的失效章段是有效区间的终点。批准后可按人物和章段查询，生成任务保留创建时所使用的设定。
- 头条可改当前标题或应用标题候选。改题后产生新修订，原修订的质检和批准仍归原版本。
- 在写作区可按当前修订和设定核算首轮预算。任务详情可查看每次写稿、质检、回改的预留及回执。旧版尝试的统计保留在尝试记录中。生成中断且缺用量时，可在 DsH 查账，将尚未入账的用量填到该任务后再重试。

停止 DsH profile 后，从源码目录备份或恢复。使用全新目标目录，恢复完成后先在隔离配置打开恢复的目录。原目录可用于回退。

```bash
node scripts/workspace-data.mjs backup <原数据目录> <全新备份目录>
node scripts/workspace-data.mjs restore <备份目录> <全新数据目录>
```

备份会生成数据库与交稿文件的 SHA-256 清单。恢复验证清单、SQLite 完整性和库格式，之后将备份里的 `work.db` 映射回宿主所需的 `workspace.sqlite`。

发版时可另外运行以下验收。浏览器脚本使用独立安装的 Playwright 和 Chromium，可通过 `ZHIZHANG_PLAYWRIGHT` 与 `ZHIZHANG_CHROMIUM` 指向现有环境。

```bash
npm run build
node scripts/model-check.mjs
npm run test:browser
node scripts/workspace-bench.mjs
```
